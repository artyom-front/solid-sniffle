## Что вообще происходит (чтобы не паниковать)

Проект **цел и работает** — я проверил: сайт поднимается, база данных живая,
тесты зелёные. Путаница возникла из-за трёх мелочей:

1. **Вы скачали архив со старой страницы.** Сообщение «problem deploying»
   отправило вас на *старую страницу генерации* — там лежит снимок тех времён,
   когда проект ещё назывался SCORES21. Поэтому в архиве «всё старое».
   Качать нужно из **текущего чата**, а не оттуда.
2. **Свежие файлы на время пропали.** Песочница перезапустилась и стёрла папку
   со скачиваниями. Я её восстановил — файлы на месте, качайте заново.
3. **Ваш GitHub ещё не видел новой версии кода.** Отсюда красный CI.
   Это лечится тремя командами — как раз ШАГ 3 ниже. Это и есть главное.

## ШАГ 1. Скачайте правильный файл

Вам нужен **один файл**: `scoresbox-update.git-bundle` (≈0,2 МБ).

**Откуда:** в этом чате — панель файлов (иконка скрепки / «Files») рядом с
последним сообщением. Если у вас есть только кнопка «All files in task» —
скачайте её архив и найдите внутри папку `download`, а в ней этот файл.

**Куда скачается:** в стандартную папку «Загрузки» (Downloads). Это нормально,
переносить его никуда не нужно — мы укажем путь в командах.

**Как проверить, что файл тот:**
- имя: `scoresbox-update.git-bundle` (если видите `scores21-…` — это старьё,
  удалите и скачайте заново из текущего чата);
- размер: примерно 219 КБ.

**Что НЕ нужно скачивать:**
- `scoresbox-full.git-bundle` (69 МБ) — запасной вариант, нужен только если
  ШАГ 3 выдаст ошибку «prerequisite commits» (см. таблицу в конце);
- `scoresbox-source.zip` — просто копия файлов для чтения, для обновления
  не подходит.

## ШАГ 2. Две проверки перед началом

**Проверка 1 — установлен ли git.** Откройте PowerShell: кнопка «Пуск» →
наберите `powershell` → Enter. В чёрно-синем окне введите:

```powershell
git --version
```

Увидели `git version 2.xx.x` — отлично. Написало «не является внутренней или
внешней командой» — установите git с
[git-scm.com/download/win](https://git-scm.com/download/win)
(установка: «Далее → Далее → Готово»), затем **закройте PowerShell и
откройте заново**.

**Проверка 2 — есть ли на компьютере папка проекта.**
Вы раньше клонировали проект и делали push — значит, папка есть, и вы знаете,
где она (например, `C:\Projects\studious-tribble`). Переходите к ШАГУ 3.

Если папки нет — сначала получите копию с GitHub:

```powershell
git clone https://github.com/artyom-front/studious-tribble.git
cd studious-tribble
```

## ШАГ 3. Три волшебные команды

Откройте PowerShell **в папке проекта** (проще всего: открыть папку в
Проводнике, потом в пустом месте окна нажать Shift + правая кнопка →
«Открыть PowerShell здесь»; в Windows 11 — правая кнопка → «Открыть в
Терминале»). Либо в уже открытом PowerShell:

```powershell
cd C:\Projects\studious-tribble   # ← замените на ваш путь к папке
```

Теперь выполняйте команды **по одной** (скопировали → вставили → Enter →
дождались):

**Команда 1 — «достань посылку»:**
```powershell
git fetch "$HOME\Downloads\scoresbox-update.git-bundle" main
```
Берёт все новые коммиты из скачанного файла. Вы увидите строки про
`From …` и `* branch main -> FETCH_HEAD`.

**Команда 2 — «замени старое на новое»:**
```powershell
git reset --hard FETCH_HEAD
```
Ваши локальные черновики заменяются эталонной версией (все важные правки
в неё уже включены). Увидите `HEAD is now at …`.

**Команда 3 — «отправь на GitHub»:**
```powershell
git push --force origin main
```
Вы увидите примерно:
`+ 30e60c2…e4c9bba main -> main (forced update)` — это успех.

## ШАГ 4. Убедитесь, что CI позеленел

Откройте страницу
[github.com/artyom-front/studious-tribble/actions](https://github.com/artyom-front/studious-tribble/actions).
Через 1–3 минуты в списке появится новый прогон — он должен стать зелёным ✅.
Если жёлтый — просто идёт сборка, подождите.

## ШАГ 5. Секреты (один раз, если ещё не делали)

GitHub → репозиторий → **Settings → Secrets and variables → Actions →
New repository secret**. Полный список секретов с примерами значений —
в `DEPLOY.md`, раздел **Б8**.

⚠️ **Важно:** значения вставляйте **без кавычек** — просто текст.
`my_password_123` ✔, а `"my_password_123"` ✘.

## ШАГ 6. Запуск деплоя (когда секреты готовы)

В том же PowerShell:

```powershell
git tag v1.0.3
git push origin v1.0.3
```

Это значит «выпустить версию v1.0.3». Тег `v…` — как кнопка «Пуск» для
деплоя: в Actions стартует сборка (5–8 минут), потом сайт появится на сервере.
Обычный `git push` деплой **не** запускает — только тег.

## Если что-то пошло не так

| Что видите | Что это и что делать |
|---|---|
| `error: repository lacks these prerequisite commits` | Ваш GitHub разошёлся сильнее, чем рассчитан маленький бандл. Скачайте `scoresbox-full.git-bundle` (69 МБ) и повторите ШАГ 3, подставив его имя в команду 1 |
| Ошибка про `merge` / `unrelated histories` | Пропущена команда 2. Выполните все три **по порядку** |
| `Authenticate failed` / просит пароль при push | GitHub давно не принимает пароль: нужен Personal Access Token (как сделать — спросите в чате, 2 минуты) |
| CI красный после обновления | Откройте прогон → красный шаг → скопируйте последние ~30 строк лога → пришлите в чат |
| Деплой не стартует после тега | Тег должен начинаться с `v`: `v1.0.4`, `v1.1.0` и т.д. Проверьте: `git tag` |
| Файл называется `scores21-…` | Это старая загрузка. Удалите и скачайте из **текущего** чата |
