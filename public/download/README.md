# Поставка SCORESBOX — v1.0.55 «feedback55» (09.10.2026)

**Что это:** 4 правки по фидбеку юзера от 09.10 (реальная эксплуатация
лиги). Главная фича — **«Штаб на матч»**: игрок может одновременно
числиться в составе и занимать должность (помощник тренера, начальник
команды…); плюс задокументирована **сквозная заявка** между первенством
и чемпионатом. Код приложения менялся, есть ОДНА миграция.

## 2. Регламентные подсказки — убраны

Блок «Красная карточка — автоматический пропуск следующего матча…
Каждые 3 жёлтые — пропуск 1 матча… КДК вправе ужесточить…» на

## 3. Сквозная заявка: первенство + чемпионат Чувашии

**Уже работало — теперь задокументировано и подсвечено в панели.**
Игрок второй команды клуба (первенство) может играть за команду
чемпионата: оформите ему ВТОРУЮ заявку — панель «Заявки» в сезоне
чемпионата → тот же человек → команда чемпионата. Переключатель
«Закрыть предыдущую заявку (трансфер)» закрывает заявки только
ТОГО ЖЕ сезона — заявка в первенстве не пострадает (у переключателя
появилась подсказка об этом). Игрок виден в протоколах обеих команд;
статистика считается по каждой команде отдельно; дисквалификации
действуют в рамках своей лиги (красная в первенстве не банит в
чемпионате). Рецепт — в ADMIN-GUIDE §8 и §9.

## 4. «Штаб на матч» — играющий сотрудник (главная фича)

Кейс юзера: «игрок является и игроком, и начальником команды, и
директором — где закладывать роли?». Роль в заявке одна (игрок ИЛИ
сотрудник), поэтому совмещение сделано на уровне матча:

- редактор протокола → вкладка «Состав» → блок **«+ В штаб на этот
  матч»**: выберите человека из заявки (в т.ч. ИГРОКА) и должность —
  «Начальник команды» (новая роль), «Помощник тренера», «Тренер»,
  «Тренер вратарей», «Администратор», «Директор», «Врач»…;
- игрок с должностью — «играющий сотрудник»: остаётся в составе
  (номер, старт/запас как обычно) И появляется в секции «Штаб»
  публичной страницы матча с подписью должности; в списке игроков
  редактора — жёлтая пометка должности;
- должность заявки-штаба (тренер/администратор из заявки) можно
  ПЕРЕОПРЕДЕЛИТЬ на матч селектором в строке — заявка не меняется;
- убрать должность — крестик (игрок остаётся в составе);
- должность живёт в протоколе матча: на следующий матч назначается
  заново (или другому человеку);
- судейская бригада матча (судьи, помощники, инспектор, делегат,
  врач) — как и раньше, на вкладке «Бригада».

API: `staffRoles: [{ personId, role }]` в action=«lineup»; мусорный
код роли или должность человеку вне состава → 422 с понятным текстом.

```bash
git fetch "$HOME\Downloads\scoresbox-2026-10-09-feedback55.git-bundle" main
git log --oneline -3 FETCH_HEAD   # «SCORESBOX 2026-10-09 feedback55: …»
git log FETCH_HEAD..main          # ПУСТО = терять нечего, безопасно
git reset --hard FETCH_HEAD && git push --force origin main
git tag v1.0.55 && git push origin v1.0.55
```

⚠️ Перед `reset --hard`: если `git log FETCH_HEAD..main` НЕ пуст —
в вашем main есть коммиты, которых нет в бандле. Сначала спрячьте
их: `git branch backup/pre-v1055 main`, и только потом reset.
Проверьте, что `git log --oneline -1 FETCH_HEAD` начинается с
«SCORESBOX 2026-10-09 feedback55: v1.0.55».

После деплоя: `/api/health` → `"version":"1.0.55"`. Строка
миграции 20261009134341_staff_role в логе деплоя — норма (бэкап БД
сделан ДО миграций).

## 6. Что проверить на проде

1. страница матча: вкладка «Протокол» — без числа событий;
2. страница «Дисциплина» лиги: подсказки про карточки не видно,
   баны/история на месте;
3. панель «Заявки»: подсказка у переключателя «трансфер» — «действует
   только внутри сезона этого турнира»;
4. редактор протокола → «Состав»: блок «+ В штаб на этот матч» —
   добавьте игрока как «Начальник команды», подайте состав →
   публичная страница: игрок и в составе с номером, и в «Штабе»;
5. POST с мусорной ролью (напрямую API) → 422 «не распознана».

**Важно:** бандл содержит ветку `main` — при клоне с нуля делайте
`git clone -b main <bundle>` (без `-b` чекаут будет пустым).

## Грабли agent-browser (задокументированы)

`agent-browser eval` держит ПЕРСИСТЕНТНЫЙ JS-контекст: top-level `const`
живёт между вызовами, повторное объявление = SyntaxError. Все
multi-statement eval — в IIFE. `find label fill` не триггерит
React-состояние (controlled input остаётся пустым, submit блокируется
нативной валидацией): в смооках логиниться демо-кнопками по email.
`find text` кликает только первый точный матч — для табов с бейджем
счётчика («Протокол · 12») клик через eval по textContent.startsWith.
Тонкость SMTP-мока: nodemailer кодирует письма (text — base64, html —
quoted-printable, тема — RFC 2047) — токен ссылки ищется только после
декодирования (см. parseMail в test-invites.ts).
