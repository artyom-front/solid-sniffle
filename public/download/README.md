# Поставка SCORESBOX — v1.0.54 «feedback54» (09.10.2026)

**Что это:** 11 правок по фидбеку юзера от 09.10 — первый запуск
реального чемпионата (создана лига, команды, один сыгранный матч
0:1). Главные: **предварительная турнирная таблица** (видна до
первого матча), **«Важный матч» только из админки** и фикс
**фантомного ассиста** у замены. Код приложения менялся.

## ⚠ ОДНА миграция БД — применится АВТОМАТИЧЕСКИ

- `20261009101830_important` — Match.isImportant (пометка «важный матч»).

deploy.sh применяет миграции сам (prisma migrate deploy) и делает
**бэкап БД до миграций**. Строка про миграцию в логе деплоя —
норма, не ошибка.

## 1. Турнирная таблица — ДО первого матча (главный баг)

Раньше список команд в таблице собирался из матчей: до первого
сыгранного матча таблица была пустой. Теперь команды берутся из
**заявок сезона** (объединение с матчевыми): создали лигу, команды,
заявили игроков — таблица уже на сайте, все команды с 0 игр и 0
очков. Команды без заявок попадают в таблицу с первым матчем.
Таб «Таблица» на странице матча тоже виден сразу.

## 2. «Важный матч» — ставит только админ

Прежний авто-алгоритм («борьба за 1-е место», «призовая зона»)
помечал важным уже ПЕРВЫЙ матч сезона — позиции при 0 игр идут по
алфавиту. Алгоритм удалён. В карточке матча (админка → Матчи →
карандаш) появился чекбокс «Важный матч»: золотая рамка + кубок в
ленте, бейдж на странице матча, пометка «важный» в списке админки.
Правится в любой момент, в том числе у завершённого матча.

## 3. Фантомный ассист у замен — исправлено

Замена в протоколе — одно событие: «вышедший + ушедший». Ушедший
хранился в поле assistPersonId — и любой заменённый игрок получал
«ассист» в статистике (ваш Артемьев Демьян). Теперь ассист
считается ТОЛЬКО передачей под гол (событие «Гол»/«Пенальти» с
ассистентом). Старые фантомные ассисты исчезнут сами — это расчёт,
не данные.

## 4. Превью матча — без нулей и «№2 в таблице»

- 0 матчей у команды → «дебют сезона» (никаких «0 очков за 0 игр»);
- с матчами → «2 место · 3 очка за 5 матчей» — нормальные слова,
  без «№», без «в таблице», с правильным согласованием;
- карточка «Самый результативный» в правой колонке — теперь от 3+
  голов: единственный гол 0:1 не объявляется «самым результативным».

## 5. Судьи — без «рейтинга»

Из профиля судьи убраны «Рейтинг», «Оценок», «Средняя оценка
капитанов» и колонка «Рейтинг» по лигам — голосований не будет.
Осталась только игровая статистика из протоколов: матчи, ЖК/матч,
КК/матч, Пен./матч.

## 6. Лайтбокс — современный просмотр фото

Клик по фото игрока/эмблеме — полноэкранный просмотр. Закрыть
МОМЕНТАЛЬНО понятно: заметная кнопка ✕ с подложкой, клик по фону,
Esc или **свайп вниз** (как в Instagram). Зум — пинч двумя
пальцами, двойной тап 1↔2 «в точку», колесо мыши «в курсор»;
приближенное фото двигается пальцем/мышью; внизу подсказка.

## 7. Составы и протокол — чистота

- составы: основной состав — светлым шрифтом, запасные
  приглушённее; между секциями нет горизонтальных линий; убраны
  счётчики «Основной состав · 11» → просто «Основной состав»;
- протокол: полосы «Перерыв 0:0» и «Завершён 0:0» — по центру
  (как бегущий счёт), текст светлее; «Завершён» в шапке матча
  тоже светлее;
- профиль игрока: «гол 24′» — типографский штрих вместо
  «&apos;», минуты добавленного времени «45+3′».

## 8. Применить и задеплоить (PowerShell, папка вашего клона)

```bash
git fetch "$HOME\Downloads\scoresbox-2026-10-09-feedback54.git-bundle" main
git log --oneline -3 FETCH_HEAD   # «SCORESBOX 2026-10-09 feedback54: …»
git log FETCH_HEAD..main          # ПУСТО = терять нечего, безопасно
git reset --hard FETCH_HEAD && git push --force origin main
git tag v1.0.54 && git push origin v1.0.54
```

⚠️ Перед `reset --hard`: если `git log FETCH_HEAD..main` НЕ пуст —
в вашем main есть коммиты, которых нет в бандле. Сначала спрячьте
их: `git branch backup/pre-v1054 main`, и только потом reset.
Проверьте, что `git log --oneline -1 FETCH_HEAD` начинается с
«SCORESBOX 2026-10-09 feedback54: v1.0.54».

После деплоя: `/api/health` → `"version":"1.0.54"`. Строка
миграции 20261009101830_important в логе деплоя — норма (бэкап БД
сделан ДО миграций).

## 9. Что проверить на проде

1. лига без сыгранных матчей: вкладка «Таблица» — все команды с 0
   игр (или матч сыгран частично — команды всё равно все);
2. админка → Матчи → карандаш → чекбокс «Важный матч» → в ленте
   у матча золотая рамка + кубок, на странице матча бейдж;
3. статистика: у заменённых игроков нет ассистов; ассист — только
   у передачи под гол;
4. превью матча: «N место · P очков за M матчей», у команд без
   матчей — «дебют сезона»;
5. фото игрока: увеличить (пинч/двойной тап), подвигать, закрыть
   свайпом вниз или кнопкой ✕;
6. судья: в профиле нет «рейтинга».

**Важно:** бандл содержит ветку `main` — при клоне с нуля делайте
`git clone -b main <bundle>` (без `-b` чекаут будет пустым).

## Грабли agent-browser (задокументированы)

`agent-browser eval` держит ПЕРСИСТЕНТНЫЙ JS-контекст: top-level `const`
живёт между вызовами, повторное объявление = SyntaxError. Все
multi-statement eval — в IIFE. `find label fill` не триггерит
React-состояние (controlled input остаётся пустым, submit блокируется
нативной валидацией): в смооках логиниться демо-кнопками по email.
`find text` кликает только первый точный матч — для табов с бейджем
счётчика («Протокол · 12») клик через eval по textContent.startsWith.
Тонкость SMTP-мока: nodemailer кодирует письма (text — base64, html —
quoted-printable, тема — RFC 2047) — токен ссылки ищется только после
декодирования (см. parseMail в test-invites.ts).
