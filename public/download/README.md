# Поставка SCORESBOX — v1.0.52 «feedback52» (08.10.2026)

**Что это:** шесть правок от владельца (08.10): дубли ФИО игроков,
мобильная вёрстка форм, один капитан на команду, единый процесс
создания игрока, модель «игрок стал тренером/директором», замены
(запасные не участвуют в событиях, пока не вышли). Код приложения
менялся; **миграций БД нет**. В бандл также вошёл недоставленный
diskfix52 (deploy.sh — чистка образов + диск-префлайт).

## 1. «Не получается создать игрока с одинаковыми ФИО» — два слоя

- **Корень бага:** `apiPost` при ошибке выбрасывал тело ответа —
  панель «Это другой человек — создать всё равно» (и умные блок-диалоги
  удаления) молча не работали. Теперь тело 409 доезжает до UI.
- **Гейт смягчён:** совпадение только Фамилии+Имени — создание проходит
  СРАЗУ (тёзки — норма), в ответе advisory-подсказка «уже есть такой
  ФИО — если дубль, используйте Merge». 409 остаётся только при
  точном совпадении **Ф+И+Отчество+даты рождения** — с кнопкой
  «всё равно создать» (которая теперь реально появляется).

## 2. Замены и события (правила состояния матча)

Новый модуль `lib/engine/match-state` — одна логика для UI и API:
«на поле» = старт + вышедшие − ушедшие; «скамейка» = запас из
протокола, ещё не выходивший.

| Событие | Кто доступен |
|---|---|
| Замена, «▲ Выходит» | **только запасные**, ещё не выходившие |
| Замена, «▼ Уходит» | **только игроки на поле** |
| Гол / пенальти / автогол / карточки / VAR | **только игроки на поле** |

Запасной, не вышедший на поле, НЕ участвует ни в одном событии.
Повторный выход (вышел → ушёл → снова вышел) запрещён. Пустые
списки в форме объясняют причину. Действует и в UI, и через API.

## 3. Капитан — один на команду

Если капитан уже назначен, отметка другого **блокируется** с
подсказкой «сначала снимите прежнего (повторный клик по его «К»)».
Смена капитана — два явных клика: снять, назначить.

## 4. Единый процесс создания игрока

Панель «Люди» → «Персона» и карточка команды → «В заявку» →
«Создать нового» теперь открывают **один и тот же бланк**
(ФИО, дата рождения, позиция, специализации). Из карточки команды
после создания бланк сразу оформляет заявку (номер/роль/дата —
одинаковые поля в обоих режимах).

## 5. Игрок стал тренером / директором — что править

Ничего «не превращается»: карточка человека одна на всю жизнь,
роли **добавляются** заявками (датированная история). Заявка с ролью
«Тренер» / «Директор» / «Тренер вратарей» автоматически добавит роль
и на карточку — получится «играющий тренер». Добавлена роль
«Директор». Подробно — ADMIN-GUIDE.md §9.

## 6. Мобильные формы («верстка едет»)

- поля ввода на телефоне — 16px (убран iOS-автозум при фокусе);
- диалоги скроллятся (max-h 92% экрана), не уезжают за экран;
- все формы в один столбец на телефоне, в два — от планшета;
- строки составов переносятся, а не обрезаются.

```bash
git fetch "$HOME\Downloads\scoresbox-2026-10-08-feedback52.git-bundle" main
git log --oneline -1 FETCH_HEAD   # «SCORESBOX 2026-10-08 feedback52: …»
git reset --hard FETCH_HEAD && git push --force origin main
git tag v1.0.52 && git push origin v1.0.52
```

⚠️ Перед `reset --hard` гляньте `git log --oneline -3 FETCH_HEAD`:
бандл собран от вашего прод-коммита 8dec5e1 (feedback46) + diskfix52;
если в вашем main есть коммиты v1.0.47–v1.0.50, которых нет в
проде — сначала сравните (`git diff FETCH_HEAD --stat`).

После: health → "version":"1.0.52". **Миграций нет.** В этом деплое
впервые заработает diskfix52: в логе деплоя появятся строки чистки
образов и диск-префлайта — это ожидаемо.

Проверка на проде: (1) создайте двух «Иванов Иван» без даты рождения —
оба создадутся; (2) такого же с датой рождения дважды — появится
предупреждение с кнопкой; (3) протокол → «Замена»: «Выходит» — только
запас, «Уходит» — только поле; гол запасному не записывается;
(4) два «К» не поставить; (5) «В заявку» → «Создать нового» — тот же
бланк, что в «Людях»; (6) откройте админку с телефона — поля в один
столбец, ввод без «разъезда».

**Важно:** бандл содержит ветку `main` — при клоне с нуля делайте
`git clone -b main <bundle>` (без `-b` чекаут будет пустым).

## Грабли agent-browser (задокументированы)

`agent-browser eval` держит ПЕРСИСТЕНТНЫЙ JS-контекст: top-level `const`
живёт между вызовами, повторное объявление = SyntaxError. Все
multi-statement eval — в IIFE. `find label fill` не триггерит
React-состояние (controlled input остаётся пустым, submit блокируется
нативной валидацией): в смооках логиниться демо-кнопками по email.
`find text` кликает только первый точный матч — для табов с бейджем
счётчика («Протокол · 12») клик через eval по textContent.startsWith.
Тонкость SMTP-мока: nodemailer кодирует письма (text — base64, html —
quoted-printable, тема — RFC 2047) — токен ссылки ищется только после
декодирования (см. parseMail в test-invites.ts).
