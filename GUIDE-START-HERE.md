# ГАЙД: добить деплой solid-sniffle — осталась ОДНА ошибка (exit 126)

> Читайте сверху вниз, по одному шагу, с проверкой после каждого шага.
> Быстрый путь — 5 минут (ШАГИ 1–3). Постоянный фикс — ещё 5 минут (ШАГИ 4–7).

---

## Что уже починено, что осталось (коротко)

**Всё главное уже зелёное:**

- ✅ **Docker-сборка** — ошибка exit 127 побеждена (фикс `USER 1001:1001`).
- ✅ **Пуш в GHCR** — ошибка `denied: installation not allowed to Create
  organization package` побеждена (блок `permissions: packages: write`).
  Доказательство из вашего лога: джоба деплоя запустилась, а на сервере
  прошла строка **`Login Succeeded`**. Образ `ghcr.io/artyom-front/solid-sniffle`
  уже лежит в реестре.

**Осталась одна, последняя ошибка:**

```
bash: line 11: ./scripts/deploy.sh: Permission denied
Process exited with status 126
```

`exit 126` = файл `scripts/deploy.sh` на сервере ЕСТЬ, но у него нет бита
исполнения `x`. В git-репозитории бит стоит (`100755`), но вы заливали файлы
на сервер с Windows (scp/архив) — Windows не хранит бит `x`, и он потерялся.
Это НЕ ошибка сборки и НЕ ошибка прав GitHub — это только про файл на VPS.

Есть два уровня лечения:

- **Путь А (быстрый, ШАГИ 1–3):** поставить бит `x` на сервере и перезапустить
  упавшую джобу — текущий прогон тега станет зелёным, новый тег не нужен.
- **Путь Б (постоянный, ШАГИ 4–7):** применить бандл `execfix` — workflow
  будет вызывать скрипты через `bash`, и деплой перестанет зависеть от бита `x`
  вообще (даже если файлы снова зальются с Windows).

Рекомендую пройти оба — сначала А, потом Б.

## Путь А — быстрый (3 шага, ~5 минут)

### ШАГ 1. Зайдите на сервер и подтвердите диагноз

В PowerShell (IP и пользователь — те же, что в секретах `DEPLOY_HOST` /
`DEPLOY_USER`; обычно `root`):

```powershell
ssh root@<IP-вашего-сервера>
```

На сервере:

```bash
cd /opt/scoresbox
ls -l scripts/deploy.sh scripts/rollback.sh
```

- Ожидаемо: `-rw-r--r--` слева (нет `x`) — это и есть причина exit 126.
- Если вдруг уже `-rwxr-xr-x` — напишите в чат, диагноз другой.

Заодно проверьте конфиг (нужен для деплоя, проверка без вывода пароля):

```bash
test -f .env && grep -q '^POSTGRES_PASSWORD=' .env && echo ".env OK" || echo ".env НЕ ГОТОВ"
```

- Ожидаемо: `.env OK`. Если «НЕ ГОТОВ» — создайте `.env` по DEPLOY.md (шаг Б3):
  `POSTGRES_PASSWORD=...`, `AUTH_SECRET=...`, `ADMIN_EMAIL=...`,
  `ADMIN_PASSWORD=...` (без кавычек, каждая с новой строки).

### ШАГ 2. Поставьте бит исполнения

На сервере (в той же папке `/opt/scoresbox`):

```bash
chmod +x scripts/deploy.sh scripts/rollback.sh
ls -l scripts/
```

- Ожидаемо: `-rwxr-xr-x` у обоих скриптов. Выйдите с сервера: `exit`.

### ШАГ 3. Перезапустите упавшую джобу — без нового тега

1. Откройте <https://github.com/artyom-front/solid-sniffle/actions>.
2. Кликните верхний красный прогон **CD / v1.0.9** (последний тег).
3. Справа вверху — кнопка **Re-run failed jobs** → подтвердите.
4. Ждите 3–6 минут (образ уже собран — пересборки не будет, пойдёт сразу
   деплой: миграции → `docker compose up` → health-check).

**Что вы должны увидеть:**

- Job **Deploy → VPS** — зелёный, в логе: `==> Деплой <тег> завершён успешно`.
- Job **Пост-деплой: внешний health-check** — зелёный, если настроен домен
  (секрет `DEPLOY_PUBLIC_URL` + nginx). Если он красный, а Deploy зелёный —
  сайт УЖЕ работает, просто домен ещё не настроен; проверьте на сервере:
  `curl -s http://127.0.0.1:3000/api/health` → должно быть `{"ok":true}`,
  и настройте nginx по DEPLOY.md.
- Job **Rollback** может остаться красным с текстом «История деплоев пуста —
  откатывать некуда» — на ПЕРВОМ деплое это не страшно (откатывать нечего).

На этом сайте уже работает новая версия — миссия выполнена.
Дальше — постоянный фикс, чтобы это не повторилось.

## Путь Б — постоянный (4 шага, ~5 минут)

Откройте в браузере (можно кликнуть прямо из чата):

Это файл **`scoresbox-2026-09-07-execfix.git-bundle`** (примерно 0,5 МБ)
с превью-сервера ЭТОГО чата.

- Панель «All files in task» показывает вложения старых сообщений и не
  обновляется — если там старые файлы, качайте по ссылке выше.
- Если ссылка отдаёт 404 — напишите в чат: я пересоберу и дам новую.

### ШАГ 5. Откройте PowerShell в папке клона и примените

```powershell
cd D:\project\scoresbox_bundle
```

Команда 1 — забрать содержимое бандла:

```powershell
git fetch "$HOME\Downloads\scoresbox-2026-09-07-execfix.git-bundle" main
```

**Проверка, что скачан именно НОВЫЙ файл** (главная защита от повтора истории):

```powershell
git log --oneline -1 FETCH_HEAD
```

- ДОЛЖНО показать: `SCORESBOX 2026-09-07 execfix: CD вызывает deploy/rollback через bash ...`
- Если показывает `SCORESBOX 2026-09-07: GITHUB_TOKEN...` (без `execfix`),
  `2026-09-04` или `v1.0.4` — это старый файл: вернитесь к ШАГУ 4.

Команда 2 — заменить локальную версию на новую:

```powershell
git reset --hard FETCH_HEAD
```

Команда 3 — отправить на GitHub:

```powershell
git push --force origin main
```

- Ожидаемо: `+ <хэш>...<хэш> main -> main (forced update)`.
- Если «Everything up-to-date» — файл опять старый: вернитесь к ШАГУ 4.

### ШАГ 6. Проверьте на GitHub, что фикс долетел (2 ссылки)

1. <https://github.com/artyom-front/solid-sniffle/blob/main/.github/workflows/cd.yml> —
   в джобе «Deploy → VPS» строка вызова должна начинаться с `bash`:
   ```yaml

   ```
   (а НЕ `./scripts/deploy.sh`).
2. <https://github.com/artyom-front/solid-sniffle/commits/main> — сверху

### ШАГ 7. Следующий тег — v1.0.10 (когда захотите задеплоить снова)

```powershell
git tag v1.0.10
git push origin v1.0.10
```

(v1.0.6–v1.0.9 указывают на старые коммиты — номера не переиспользовать.)

С этого момента деплой не зависит от бита `x`: даже если файлы на сервер
снова попадут с Windows без бита исполнения, `bash scripts/deploy.sh`
отработает.
