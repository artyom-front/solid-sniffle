# ADMIN-GUIDE · SCORESBOX — база знаний администратора

Версия 1.0.42 (05.10.2026). Этот документ — единый справочник логики панели
управления: роли, пароли, жизненный цикл турниров, правила удаления, безопасность.
Тренируйте сотрудников по нему; сайт перегружаться подсказками не будет.

## 1. Роли и доступы

| Роль | Что видит и делает | Чего не видит |
|---|---|---|
| **СУПЕР-АДМИНИСТРАТОР** | Всё: турниры, справочники, контент сайта (баннеры, стат-карточки, виды футбола), пользователи и доступы, журнал изменений, merge профилей | — |
| **АДМИНИСТРАТОР ЛИГИ** (без привязки) | Турнирное ядро всех лиг: сезоны, матчи, расписание, протоколы, КДК, справочники, заявки, импорт | Контент сайта, пользователи, журнал изменений, merge |
| **АДМИНИСТРАТОР КОНКРЕТНОЙ ЛИГИ** (привязка к лиге) | То же, но ТОЛЬКО в своей лиге: её сезоны/матчи/протоколы/заявки/КДК; в списке лиг — только она; дашборд и алерты — только её матчи | Чужие лиги, товарищеские матчи, создание/удаление лиг, контент сайта, пользователи |
| **АДМИНИСТРАТОР КЛУБА (команд)** | Справочники, заявки и трансферы — только по командам своего клуба; импорт составов | Чужие клубы, турнирное ядро, контент сайта |
| **СУДЬЯ** | Протоколы матчей, назначенных лично ему (с привязкой к персоне) | Всё остальное |
| **ИГРОК** | Личный профиль на сайте | Панель управления |

Правила:
- Привязку к лиге задаёт и снимает **только супер-администратор** (панель
  «Пользователи» → кнопка «Лига»). Смена роли с «администратора лиги» на любую
  другую снимает привязку автоматически.
- Пользователь ниже супер-админа **не имеет доступа к чужим профилям**:
  раздел «Пользователи» и API пользователей закрыты; свой профиль и пароль —
  в разделе «Безопасность».
- Все действия фиксируются в **журнале изменений** (кто, что, когда, старое →
  новое значение). Журнал — только у супер-администратора.

### Гарантии API по ролям (v1.0.42 — аудит 05.10.2026)

Бэкенд закрывает сущности «вне скоупа» на каждом запросе — ID, подсмотренный
или подобранный, доступ не даёт (защита от BOLA/IDOR):

- **Контент сайта** (баннеры, стат-карточки, виды футбола, merge) — API
  строго SUPER_ADMIN, как и в панели. Раньше бэкенд допускал админа лиги —
  в обход скрытых пунктов меню.
- **Протокол/заявки/КДК** — админ конкретной лиги не может открыть/изменить
  их в чужой лиге по прямому ID (в т.ч. чтение протокола и удаление чужой КДК).
- **Персоны** — клубный администратор редактирует только «своих» (заявка в
  команду его клуба; свободные профили без заявок — ничьи) и только
  паспортные поля. **Роли и статус судьи** персоны меняет администратор
  лиги или супер-администратор.
- **Дашборд** — каждому ролям своя картина: супер — сайт; админ лиги — своя
  лига; клуб — матчи команд своего клуба; судья — назначенные ему матчи.
  «Свежие изменения» (журнал с email) — только у супер-админа.
- **Медиатека** — удалять файлы может только супер-администратор (у файлов
  пока нет модели владения; загрузка доступна всем ролям панели).

## 2. Пароли и приглашения — золотой стандарт

- **Никто не задаёт и не видит чужой пароль, включая супер-администратора.**
- Новый пользователь создаётся **без пароля** — ему отправляется
  **приглашение**: одноразовая ссылка установки пароля. Открыв её,
  человек видит email аккаунта, **подтверждает его** (или исправляет
  опечатку — смена видна админу бейджем «почта не подтверждена») и
  задаёт пароль сам.
- **SMTP-режим (рекомендуется, `.env` → `SMTP_HOST` …):** приглашение и
  сброс пароля уходят **письмом на email пользователя**. Ссылку не
  видит никто, кроме получателя: клик по письму доказывает, что ящик
  принадлежит именно ему. Опечатка в адресе обнаруживается сама —
  письмо не доходит, приглашение «не принято» (бейдж «без пароля»).
- **Ручной режим (SMTP не задан):** одноразовая ссылка показывается
  супер-админу и передаётся человеку лично/мессенджером. Подтверждение
  адреса происходит при установке пароля. Это режим совместимости —
  включите почту, как только появится SMTP-аккаунт.
- Виды ссылок: **приглашение — 48 часов** (письмо может ждать прочтения),
  **сброс пароля — 15 минут**. Обе одноразовые: срабатывают единожды,
  после установки пароля закрываются и все прежние входы аккаунта.
- **Забытый пароль:** Пользователи → «Сброс пароля» (письмо или ссылка,
  зависит от режима). Пароль знает только сам человек.
- **Смена почты:** Пользователи → «Почта». Новый адрес требует
  подтверждения пользователем (письмо-приглашение в SMTP-режиме);
  прежний адрес перестаёт быть логином сразу.
- **Смена собственного пароля** — раздел «Безопасность»: требует **текущий
  пароль** (при включённой 2FA — ещё и код из приложения). Украденная сессия
  не позволяет перехватить аккаунт. После смены закрываются все другие входы.
- Ограничения: минимум 8 символов; новый не должен совпадать с текущим.
- Пароли хранятся как scrypt-хэши; вход ограничен 10 неудачными попытками
  в минуту с IP; все входы журналируются.
- 2FA (TOTP): каждый включает себе сам в «Безопасности». Сброс 2FA
  (потерян телефон) — супер-админ, аварийная кнопка.

### Настройка почты (SMTP)

1. Заведите почтовый ящик для рассылки (например `no-reply@scoresbox.ru`
   в Яндекс 365) и **пароль приложения** для него.
2. В `.env` на сервере задайте:
   `SMTP_HOST=smtp.yandex.ru`, `SMTP_PORT=465`, `SMTP_SECURE=true`,
   `SMTP_USER=no-reply@scoresbox.ru`, `SMTP_PASS=…`,
   `MAIL_FROM="SCORESBOX <no-reply@scoresbox.ru>"`.
   (587 + STARTTLS — вариант для корпоративных релеев; подробнее —
   `.env.example`, раздел «Почта».)
3. `docker compose … up -d` (переменные пробрасываются через env_file)
   — панель «Пользователи» покажет зелёный баннер «Письма включены».
4. Проверьте: создайте тестового пользователя и убедитесь, что письмо
   дошло (в т.ч. не в «Спам»). Яндекс требует подтверждённый домен
   отправителя для писем со ссылками.

## 3. Жизненный цикл турнира

```
ЛИГА (формат 11×11 / 8×8 / 5×5, дисциплинарные правила, техпоражение)
  └─ СЕЗОН (у лиги один «текущий»; на сезон заводится этап)
       ├─ ЗАЯВКИ (Registration: человек + команда + сезон; история заявок
       │   разрешена — игрок может уйти и вернуться; активная заявка одна)
       ├─ РАСПИСАНИЕ (генератор round-robin) или матчи вручную
       └─ МАТЧ → ПРОТОКОЛ (составы → события → Завершить)
```

Порядок запуска нового чемпионата: создать лигу (формат, лимиты ЖК/КК,
регламентный счёт техпоражения) → создать сезон (отметить «текущий»,
этап создастся автоматически) → завести клубы/команды/людей → заявить
игроков по командам → сгенерировать или создать матчи → назначить судей
и бригады → вводить протоколы по ходу тура.

**Предварительная таблица (v1.0.54):** как только в сезоне есть заявки —
турнирная таблица уже показывается на сайте: все команды с 0 игр и 0
очков, места по алфавиту. Ждать первого сыгранного матча не нужно. Если
команды созданы без заявок, они попадут в таблицу с первым матчем.

**«Важный матч» (v1.0.54):** пометка в карточке матча (чекбокс рядом с
полем «Тур»): золотая рамка и кубок в ленте, бейдж на странице матча.
Ставится только администратором — дерби, матч за 1-е место, плей-офф
решаете вы (авто-алгоритм удалён: число кругов лиги заранее неизвестно).
Правится в любой момент, в том числе у завершённого матча.

Товарищеские матчи — вне лиг и сезонов: без туров, таблиц, статистики
и дисциплины. Ведут оператор сайта или супер-админ (администратор
конкретной лиги их не видит).

## 4. Протокол матча

Вкладки редактора: **Состав** (старт → номера → запас → штаб), **События**
(голы, карточки, замены; минуты 45+X; участник — только из заявленного
состава; замена — одно событие с двумя игроками), **Бригада** (главный судья
+ помощники/резервный/VAR/инспектор/делегат/врач; одна роль на персону),
**Файл** (скан/фото бумажного протокола, до 10 МБ), **Завершение**.

Правила:
- Черновики (состав, бригада, незасохранённые события) **переживают
  переключение вкладок**.
- Матч не завершается **без главного судьи**.
- «Завершить» считает счёт, применяет дисциплину (КК → бан, накопление ЖК
  по лимиту лиги, отсиживание матчей) и закрывает протокол.
- После завершения правятся только **безопасные поля**: дата, стадион, тур,
  примечание, бригада. Изменить команды, статус или события — сначала
  **«Вернуть в работу»** (Reset; только супер-администратор): откатывает
  счёт и дисциплинарные последствия, события остаются для правки.
- **Техпоражение (WO)**: назначается вместо ввода протокола; события и
  составы матча при этом очищаются, счёт подставляется регламентный.
- **Замены ≠ ассисты (v1.0.54)**: замена — одно событие «вышедший +
  ушедший»; раньше «ушедший» ошибочно получал ассист в статистике.
  Ассист считается только передачей под гол (событие «Гол» с ассистентом).

### Судейский корпус (v1.0.34) — одна роль, должность в матче

Раньше при создании человека приходилось выбирать узкую специальность
(«помощник судьи», «инспектор»…) — и тогда он не появлялся в списке главных
судей, а инспектор «виден, но не может быть судьёй». Теперь:

- На карточке человека — **одна роль «Судья (судейский корпус)»**. Человек —
  представитель корпуса; кем он будет в конкретном матче (главный, помощник,
  резервный, VAR, инспектор, делегат) — выбирается при назначении.
- Списки «Главный судья» в форме матча и бригаде протокола показывают
  **весь корпус**. Врач в них не попадает — врач назначается только в
  бригаду.
- **Судья может быть игроком** (карточка «Игрок + Судья») — играют в одной
  лиге, судят другую. Запрет один и точный: **нельзя в одном чемпионате и
  сезоне** — система не даст ни заявить игрока, который судит этот сезон,
  ни назначить в бригаду заявленного игрока (409 с пояснением).
- Конфликт интересов: нейтральное лицо не обслуживает **матчи своей
  команды** (даже как тренер).
- **Капитан (v1.0.34)**: во вкладке «Состав» у каждого игрока кнопка «К» —
  один капитан на команду в этом матче (меняется от матча к матчу).
  На сайте капитан помечен жёлтой плашкой «К» в составе.

### Люди: поиск и страницы (v1.0.34)

- Поиск в «Людях» — **серверный и регистронезависимый**: «мамонтов» найдёт
  «Мамонтов». Ищет в фамилии, имени и отчестве.
- Список — **постраничный** (50 на страницу, компактные номера страниц):
  больше никакой «портянки» и обрезки списка на 200-й записи.
- Защита от дублей при создании — **предупреждение, а не запрет**: система
  показывает похожих людей (ФИО, дата рождения, команды) и кнопки
  «Открыть карточку» / «Это другой человек — создать всё равно». Неточных
  данных (только имя и фамилия)? Создавайте смело — позже профили
  объединяются в разделе **«Merge профилей»** (судьи, заявки, события,
  дисквалификации переезжают на пережившего).

### Навигация в панели (v1.0.34)

- Позиция в панели (раздел, лига, сезон, открытый матч, карточка команды
  или человека) — в адресе страницы: ссылкой можно **поделиться**, F5 и
  «назад/вперёд» браузера **восстанавливают позицию**.
- Кнопка «назад» браузера **ходит по разделам панели**, а не выкидывает на
  публичный сайт. Открытие матча/карточки — как отдельная страница в
  истории.
- Смена раздела закрывает открытый протокол матча (раньше он «залипал»
  поверх других разделов).

### Адаптив публичного сайта (v1.0.34, строки матчей — v1.0.35, фикс ленты — v1.0.36)

Три колонки упрощаются поэтапно: от 1424 px — лиги + лента + статистика;
1120–1423 px — **лента + статистика** (лиги прячутся, навигация по лигам —
сворачивается вверху ленты); ниже 1120 px — только лента, статистика —
витриной под ней. Рекламные слоты LEFT_* видны только с боковой колонкой
(от 1424 px); TOP/BOTTOM — во всех режимах; BACKGROUND — от 1120 px.

**Строки матчей на телефоне (v1.0.35, паттерн FlashScore/SofaScore).**
Ниже 640 px (вплоть до iPhone SE 375 px) команды идут **друг под
другом**: имя слева, счёт — по цифре справа на строке своей команды
(`[время] Хозяева ···2 / [значок] Гости ···1`). То же — в календаре
лиги, витрине «Матч тура» и шапке страницы матча (герб + имя строки,
счёт крупно справа, статус снизу). Техника — CSS-грид +
`display:contents` для бейджа счёта: десктоп не изменился ни на пиксель.
Заголовки лиг на телефоне: кегль 12 px, чип формата скрыт (формат уже
выбран фильтром в шапке), шеврон скрыт — длинные имена читаются целиком.

**Фикс ленты v1.0.36.** В основной ленте имя хозяев «уплывало» вправо
(грабля `flex-row-reverse` без justify: в row-reverse flex-start
упаковывает контент к ПРАВОМУ краю), из-за чего имена стояли
кто слева, кто справа, а значки-сигналы скакали. Исправлено: DOM-порядок
равен мобильному порядку чтения (имя → значки, упаковка влево),
десктоп разворачивает `sm:flex-row-reverse` — без изменений на sm+.
Верифицировано на 375 px: имена обеих команд на одном X, цифры
выровнены по правому краю, переполнения нет.

## 5. Удаление — что уходит, что остаётся

Принцип: **удаляются детали, мастер-данные остаются.** Перед каждым
необратимым удалением интерфейс показывает список последствий.

### Матч (в т.ч. завершённый, с протоколом)
- **Удаляется навсегда:** события (голы/карточки/замены), составы, бригада,
  оценка судейства, файл протокола; авто-дисквалификации, порождённые этим
  матчем; вклад матча в таблицу/бомбардиров/статистику (пересчёт автоматом).
- **Остаётся:** игроки, команды, клубы, стадионы, судьи, заявки на сезон.
- Массовое удаление работает так же; «пропущенных с протоколом» больше
  не бывает — раньше эти матчи застревали в списке навсегда.

### Другие сущности
- **Сезон** — удаляется только без матчей/заявок/дисквалификаций
  (защита от потери турнирной истории; иначе кнопка объясняет, что мешает).
- **Лига** — только без сезонов и матчей.
- **Команда** — с активными заявками не удаляется: кнопка предлагает
  удалить вместе с заявками (турнирной истории при этом не теряется,
  матчи не затрагиваются) или открыть карточку.
- **Человек (персона)** — заблокирован историей (заявки/события/назначения).
  Дубликаты объединяются через **Merge профилей** (супер-админ), а не удалением.
- **Пользователь** — удалять не нужно: отключите вход (кнопка «Отключить»).
- **Формат/стат-карточка/баннер** — контент сайта, удаляется свободно
  (только супер-админ).

## 6. Обновление данных в панели

- Данные обновляются **сами** каждые 30 секунд (пока вкладка браузера видима):
  обзор, дашборд, списки протоколов. Незасохранённые формы и черновики
  при этом **не сбрасываются**.
- После любого действия (создал/изменил/удалил) список обновляется сразу.
- **F5 больше не сбрасывает на дашборд**: раздел, лига и сезон хранятся
  в адресе (`/admin?section=matches&league=…&season=…`), после обновления
  страницы вы возвращаетесь на то же место. Прямые ссылки на разделы
  и открытый матч можно закладывать и рассылать.
- Дашборд утилитарный: каждая карточка-метрика кликабельна и ведёт в
  раздел, где с ней работают («протоколов к вводу» → протоколы,
  «без судьи» → матчи, «активных дисквалов» → КДК). Блок «Требуют
  внимания» — приоритетная очередь: LIVE, незакрытые протоколы,
  матчи без судьи за 48 часов.

## 7. Безопасность — что уже есть и что рекомендуется

### Скрытие панели и защита от брутфорса — золотой стандарт

Частый вопрос: «вдруг найдут адрес /admin и начнут перебирать пароли?».
Отраслевой стандарт (WordPress/wp-admin, облачные консоли, банки): **тайный
URL — НЕ защита** (security through obscurity); защиту обеспечивают
аутентификация, замедление и наблюдаемость. Что уже стоит в SCORESBOX:

- **Панель не индексируется**: robots.txt + заголовок `X-Robots-Tag: noindex`
  для /admin и /api — поисковики адрес не узнают, в выдаче не появится.
- **Брутфорс-лимит**: 10 неудачных входов в минуту с одного IP → 429 с
  паузой. Успешные входы лимит не тратят (честных не запираем).
- **2FA (TOTP)**: даже угаданный пароль без кода с телефона бесполезен.
- **Единый ответ на неверную пару email/пароль** («Неверный email или
  пароль») — злоумышленник не узнает, существует ли аккаунт.
- **Сессии с версионированием**: смена пароля/2FA мгновенно закрывает все
  выданные cookie.
- **CSP/X-Frame-Options/nosniff** + Origin-проверка на мутациях (CSRF).

Дальше по нарастающей (опционально, по мере роста аудита):
1. **2FA у всех админов** — обязательная часть онбординга (см. ниже).
2. **IP-allowlist на уровне reverse-proxy** (Caddy/nginx): если админы
   работают из фиксированных офисных сетей — ограничить /admin списком IP,
   остальным 404. Меняется одной строкой в Caddyfile.
3. **Вынос панели на поддомен** (`admin.scoresbox.ru`) с отдельным
   журналом доступа и (при росте) WAF/Cloudflare перед ним.
4. Мониторинг журнала изменений и входов: регулярный просмотр
   «Журнала изменений» (только супер-админ) + alert на серию 429.

Рекомендуется держать:
1. **2FA у всех админов** — обязательная часть онбординга сотрудника.
2. **Принцип наименьших привилегий**: сотруднику — скоуп его лиги/клуба,
   а не «админ всего». Доступ к сайту целиком — только владельцу.
3. Отдельный аккаунт каждому человеку; общих аккаунтов не заводить
   (журнал изменений станет бесполезен).
4. **Бэкапы БД** перед массовым удалением: деплой делает pg_dump
   автоматически; при ручных чистках запустите `scripts/backup-db.sh`.
5. Пересматривать список активных пользователей раз в месяц (уволенные
   и ушедшие из федерации — «Отключить»).

### Техническое: регистронезависимый поиск (грабля locale)

postgres:16-alpine без настроек создаёт базу с locale=C/SQL_ASCII —
SQL-функции LOWER()/ILIKE **не складывают кириллицу**, и «стандартный»
регистронезависимый поиск молча не работает. В v1.0.34 поиск людей
(админка + публичный) и проверка дублей ФИО сверяют регистр **на стороне
приложения** — работает на любой конфигурации. Если захотите штатные
средства (ILIKE-индексы, сортировка по алфавиту) — пересоздайте базу
в UTF8 (pg_dump → initdb с `--encoding=UTF8 --locale=C.UTF-8` → restore,
инструкция в DEPLOY.md); приложение от этого не зависит.

### Реклама — как расставлять (золотой стандарт)

Слоты и поведение: **TOP/BOTTOM** — полосы 90 px внутри ленты, видны на
всех разрешениях; **LEFT_*/RIGHT_*** — боковые колонки (LEFT — только
от 1200 px, RIGHT — от 768 px); **BACKGROUND** — фоновая заливка по
краям ленты. **Страница матча (v1.0.41)** — боковых колонок нет на всех
ширинах: слоты **TOP + RIGHT_TOP + RIGHT_BOTTOM** показываются РЯДОМ
ИЗ 3 НАД матчем (на телефоне — горизонтальная карусель со свайпом,
высота 90 px, не три этажа). Настройка — те же баннеры в разделе
«Реклама», отдельного слота заводить не нужно. Правила, чтобы реклама
не ломала вёрстку:
- боксы **фиксированной высоты** (анти-CLS: контент не прыгает при
  загрузке баннера);
- картинки — `cover/contain/repeat` на выбор, обрезка по боксу;
- обязательна маркировка «Реклама» (размер/прозрачность настраиваются);
- на мобильных (<768 px) прочих страниц живёт только TOP/BOTTOM —
  боковые слоты сами исчезают вместе с колонками, вёрстка не ломается;
- сроки показа (startsAt/endsAt) и приоритет — для ротации кампаний.
6. Не выкладывать этот файл и ссылки `?pwset=` в общие чаты: ссылка
   установки пароля — секрет уровня пароля.
7. Включить SMTP-рассылку (раздел 2): пока ссылки передаются руками,
   опечатка в адресе обнаруживается только самим человеком.

## 8. Частые сценарии

- **«Не удаляется матч»** — больше не бывает: любой матч (включая сыгранный)
  удаляется через корзину на строке с предупреждением о том, что уйдёт.
- **«Хочу пересчитать таблицу после удаления»** — ничего делать не нужно:
  таблица/бомбардиры/дисциплина считаются из событий на лету.
- **«Сотрудник забыл пароль»** — Пользователи → «Сброс пароля»:
  письмо со ссылкой (SMTP) или ссылка для передачи лично (15 минут,
  один раз).
- **«Приглашение не дошло / письмо не приходит»** — проверьте бейдж
  «почта не подтверждена» и адрес (кнопка «Почта»), папку «Спам»,
  настройки SMTP в `.env`; затем «Приглашение» → повторная отправка.
- **«Человек вошёл и говорит: email неверный»** — Пользователи →
  «Почта» → введите верный адрес: пользователю уйдёт письмо-приглашение
  для подтверждения (в ручном режиме — ссылка).
- **«Судья не видит свой матч»** — проверьте: пользователь-судья привязан
  к персоне, и матч назначен именно этой персоне (поле «Главный судья»).
- **«Матч завершён, надо поменять счёт/событие»** — вкладка «Завершение» →
  «Вернуть в работу» (супер-админ) → правьте протокол → снова «Завершить».
- **«Задвоили игрока»** — не удалять, а объединить: «Merge профилей».
- **«Админ лиги не видит чужую лигу»** — так задумано (скоуп); расширить
  или сменить лигу может супер-админ в «Пользователях» → «Лига».

## 9. Персона и её роли (v1.0.52) — золотой стандарт

Один человек = одна карточка на всю жизнь. Человек НЕ «превращается»
из игрока в тренера — он **добавляет** роли. Так устроены Transfermarkt,
РФС и все крупные системы: личность отделена от должностей.

**Три уровня модели:**

| Уровень | Что это | Где правится |
|---|---|---|
| **Персона (карточка)** | Личность: ФИО, дата рождения, фото, специализации («кем является») | Раздел «Люди» → карточка |
| **Заявка (Registration)** | Роль в КОНКРЕТНОЙ команде на период: игрок, тренер, директор… | Карточка команды → «В заявку» / панель «Заявки» |
| **Должность в матче** | Судья-главный/помощник, инспектор, делегат — назначение на матч | Протокол → «Бригада» |

**Игрок стал тренером/директором через год — как оформить:**
1. Откройте его карточку («Люди» → клик по имени) — это «основной профиль»:
   паспортные данные там и правятся (фото, ФИО, ДР).
2. Заведите ЗАЯВКУ с нужной ролью: карточка команды → «В заявку» →
   «Найти существующего» → роль «Тренер» / «Директор» / «Тренер вратарей»
   и т.д. Дата заявки — с какого числа он приступил.
3. Роль на карточке добавится АВТОМАТИЧЕСКИ (синхронизация v1.0.52) —
   «Игрок» никуда не денется: получите «играющего тренера».
   В другом сезоне он может быть игроком, в третьем — директором:
   история заявок всё покажет (карточка персоны → «Заявки»).
4. Ошиблись — заявку можно закрыть датой (отзаявить) или удалить
   (если матчей не было); карточку не трогайте.

**Почему не «редактировать в основном профиле»?** Основной профиль
хранит ЛИЧНОСТЬ (одну на человека). Роли в командах — датированные
записи (история «когда и кем был»), их может быть много параллельно
(игрок в одной лиге + тренер в другой). Если бы роль жила только
на карточке, пропала бы история: «в 2026-м он был директором „Вектора"».

**Создание игрока — один процесс (v1.0.52):** панель «Люди» → «Персона»
и карточка команды → «В заявку» → «Создать нового» открывают ОДИН И ТОТ ЖЕ
бланк (PersonFields): ФИО, дата рождения, позиция, специализации.
Разница только в контексте: из карточки команды после создания бланк
сразу оформляет заявку. Тёзки (одинаковые Ф+И) создаются свободно;
точное совпадение ФИО+даты рождения попросит подтверждения («это другой
человек?»), дубль лечится через «Merge профилей».

**Замены и события (v1.0.52):** в протоколе события записываются только
игрокам НА ПОЛЕ. Запасной появляется в списках ТОЛЬКО в событии «Замена»
(«Выходит» — запасные, «Уходит» — игроки на поле). Гол/карточка запасному,
не выходившему на поле, не запишутся ни в интерфейсе, ни через API.
Повторный выход замены (вышел → ушёл → вышел) запрещён.
