# ADMIN-GUIDE · SCORESBOX — база знаний администратора

Версия 1.0.32 (26.09.2026). Этот документ — единый справочник логики панели
управления: роли, пароли, жизненный цикл турниров, правила удаления, безопасность.
Тренируйте сотрудников по нему; сайт перегружаться подсказками не будет.

---

## 1. Роли и доступы

| Роль | Что видит и делает | Чего не видит |
|---|---|---|
| **СУПЕР-АДМИНИСТРАТОР** | Всё: турниры, справочники, контент сайта (баннеры, стат-карточки, виды футбола), пользователи и доступы, журнал изменений, merge профилей | — |
| **АДМИНИСТРАТОР ЛИГИ** (без привязки) | Турнирное ядро всех лиг: сезоны, матчи, расписание, протоколы, КДК, справочники, заявки, импорт | Контент сайта, пользователи, журнал изменений, merge |
| **АДМИНИСТРАТОР КОНКРЕТНОЙ ЛИГИ** (привязка к лиге) | То же, но ТОЛЬКО в своей лиге: её сезоны/матчи/протоколы/заявки/КДК; в списке лиг — только она; дашборд и алерты — только её матчи | Чужие лиги, товарищеские матчи, создание/удаление лиг, контент сайта, пользователи |
| **АДМИНИСТРАТОР КЛУБА (команд)** | Справочники, заявки и трансферы — только по командам своего клуба; импорт составов | Чужие клубы, турнирное ядро, контент сайта |
| **СУДЬЯ** | Протоколы матчей, назначенных лично ему (с привязкой к персоне) | Всё остальное |
| **ИГРОК** | Личный профиль на сайте | Панель управления |

Правила:
- Привязку к лиге задаёт и снимает **только супер-администратор** (панель
  «Пользователи» → кнопка «Лига»). Смена роли с «администратора лиги» на любую
  другую снимает привязку автоматически.
- Пользователь ниже супер-админа **не имеет доступа к чужим профилям**:
  раздел «Пользователи» и API пользователей закрыты; свой профиль и пароль —
  в разделе «Безопасность».
- Все действия фиксируются в **журнале изменений** (кто, что, когда, старое →
  новое значение). Журнал — только у супер-администратора.

## 2. Пароли — золотой стандарт

- **Никто не задаёт и не видит чужой пароль, включая супер-администратора.**
- Новый пользователь создаётся **без пароля**: система выдаёт **одноразовую
  ссылку** (`/admin?pwset=…`), которую супер-админ передаёт человеку лично или
  по защищённому каналу. Ссылка живёт **15 минут и срабатывает один раз**.
- Забытый пароль: супер-админ нажимает «Ссылка на пароль» → новая одноразовая
  ссылка → человек сам задаёт новый пароль. Все прежние входы аккаунта при
  этом закрываются.
- **Смена собственного пароля** — раздел «Безопасность»: требует **текущий
  пароль** (при включённой 2FA — ещё и код из приложения). Украденная сессия
  не позволяет перехватить аккаунт. После смены закрываются все другие входы.
- Ограничения: минимум 8 символов; новый не должен совпадать с текущим.
- Пароли хранятся как scrypt-хэши; вход ограничен 10 неудачными попытками
  в минуту с IP; все входы журналируются.
- 2FA (TOTP): каждый включает себе сам в «Безопасности». Сброс 2FA
  (потерян телефон) — супер-админ, аварийная кнопка.

## 3. Жизненный цикл турнира

```
ЛИГА (формат 11×11 / 8×8 / 5×5, дисциплинарные правила, техпоражение)
  └─ СЕЗОН (у лиги один «текущий»; на сезон заводится этап)
       ├─ ЗАЯВКИ (Registration: человек + команда + сезон; история заявок
       │   разрешена — игрок может уйти и вернуться; активная заявка одна)
       ├─ РАСПИСАНИЕ (генератор round-robin) или матчи вручную
       └─ МАТЧ → ПРОТОКОЛ (составы → события → Завершить)
```

Порядок запуска нового чемпионата: создать лигу (формат, лимиты ЖК/КК,
регламентный счёт техпоражения) → создать сезон (отметить «текущий»,
этап создастся автоматически) → завести клубы/команды/людей → заявить
игроков по командам → сгенерировать или создать матчи → назначить судей
и бригады → вводить протоколы по ходу тура.

Товарищеские матчи — вне лиг и сезонов: без туров, таблиц, статистики
и дисциплины. Ведут оператор сайта или супер-админ (администратор
конкретной лиги их не видит).

## 4. Протокол матча

Вкладки редактора: **Состав** (старт → номера → запас → штаб), **События**
(голы, карточки, замены; минуты 45+X; участник — только из заявленного
состава; замена — одно событие с двумя игроками), **Бригада** (главный судья
+ помощники/резервный/VAR/инспектор/делегат/врач; одна роль на персону),
**Файл** (скан/фото бумажного протокола, до 10 МБ), **Завершение**.

Правила:
- Черновики (состав, бригада, незасохранённые события) **переживают
  переключение вкладок**.
- Матч не завершается **без главного судьи**.
- «Завершить» считает счёт, применяет дисциплину (КК → бан, накопление ЖК
  по лимиту лиги, отсиживание матчей) и закрывает протокол.
- После завершения правятся только **безопасные поля**: дата, стадион, тур,
  примечание, бригада. Изменить команды, статус или события — сначала
  **«Вернуть в работу»** (Reset; только супер-администратор): откатывает
  счёт и дисциплинарные последствия, события остаются для правки.
- **Техпоражение (WO)**: назначается вместо ввода протокола; события и
  составы матча при этом очищаются, счёт подставляется регламентный.

## 5. Удаление — что уходит, что остаётся

Принцип: **удаляются детали, мастер-данные остаются.** Перед каждым
необратимым удалением интерфейс показывает список последствий.

### Матч (в т.ч. завершённый, с протоколом)
- **Удаляется навсегда:** события (голы/карточки/замены), составы, бригада,
  оценка судейства, файл протокола; авто-дисквалификации, порождённые этим
  матчем; вклад матча в таблицу/бомбардиров/статистику (пересчёт автоматом).
- **Остаётся:** игроки, команды, клубы, стадионы, судьи, заявки на сезон.
- Массовое удаление работает так же; «пропущенных с протоколом» больше
  не бывает — раньше эти матчи застревали в списке навсегда.

### Другие сущности
- **Сезон** — удаляется только без матчей/заявок/дисквалификаций
  (защита от потери турнирной истории; иначе кнопка объясняет, что мешает).
- **Лига** — только без сезонов и матчей.
- **Команда** — с активными заявками не удаляется: кнопка предлагает
  удалить вместе с заявками (турнирной истории при этом не теряется,
  матчи не затрагиваются) или открыть карточку.
- **Человек (персона)** — заблокирован историей (заявки/события/назначения).
  Дубликаты объединяются через **Merge профилей** (супер-админ), а не удалением.
- **Пользователь** — удалять не нужно: отключите вход (кнопка «Отключить»).
- **Формат/стат-карточка/баннер** — контент сайта, удаляется свободно
  (только супер-админ).

## 6. Обновление данных в панели

- Данные обновляются **сами** каждые 30 секунд (пока вкладка браузера видима):
  обзор, дашборд, списки протоколов. Незасохранённые формы и черновики
  при этом **не сбрасываются**.
- После любого действия (создал/изменил/удалил) список обновляется сразу.
- **F5 больше не сбрасывает на дашборд**: раздел, лига и сезон хранятся
  в адресе (`/admin?section=matches&league=…&season=…`), после обновления
  страницы вы возвращаетесь на то же место. Прямые ссылки на разделы
  и открытый матч можно закладывать и рассылать.
- Дашборд утилитарный: каждая карточка-метрика кликабельна и ведёт в
  раздел, где с ней работают («протоколов к вводу» → протоколы,
  «без судьи» → матчи, «активных дисквалов» → КДК). Блок «Требуют
  внимания» — приоритетная очередь: LIVE, незакрытые протоколы,
  матчи без судьи за 48 часов.

## 7. Безопасность — что уже есть и что рекомендуется

Есть: 2FA (TOTP + резервные коды), одноразовые ссылки на пароль, скоупы
ролей, контроль версий сессий (сброс пароля/2FA мгновенно закрывает все
входы), журналирование всех действий, rate-limit входа и API, CSP/HSTS,
брутфорс-лимит, скрытие демо-аккаунтов на проде (`SHOW_DEMO_ACCOUNTS=0`).

Рекомендуется держать:
1. **2FA у всех админов** — обязательная часть онбординга сотрудника.
2. **Принцип наименьших привилегий**: сотруднику — скоуп его лиги/клуба,
   а не «админ всего». Доступ к сайту целиком — только владельцу.
3. Отдельный аккаунт каждому человеку; общих аккаунтов не заводить
   (журнал изменений станет бесполезен).
4. **Бэкапы БД** перед массовым удалением: деплой делает pg_dump
   автоматически; при ручных чистках запустите `scripts/backup-db.sh`.
5. Пересматривать список активных пользователей раз в месяц (уволенные
   и ушедшие из федерации — «Отключить»).
6. Не выкладывать этот файл и ссылки `?pwset=` в общие чаты: ссылка
   установки пароля — секрет уровня пароля.

## 8. Частые сценарии

- **«Не удаляется матч»** — больше не бывает: любой матч (включая сыгранный)
  удаляется через корзину на строке с предупреждением о том, что уйдёт.
- **«Хочу пересчитать таблицу после удаления»** — ничего делать не нужно:
  таблица/бомбардиры/дисциплина считаются из событий на лету.
- **«Сотрудник забыл пароль»** — Пользователи → «Ссылка на пароль» →
  передать ссылку. Пятнадцать минут, один раз.
- **«Судья не видит свой матч»** — проверьте: пользователь-судья привязан
  к персоне, и матч назначен именно этой персоне (поле «Главный судья»).
- **«Матч завершён, надо поменять счёт/событие»** — вкладка «Завершение» →
  «Вернуть в работу» (супер-админ) → правьте протокол → снова «Завершить».
- **«Задвоили игрока»** — не удалять, а объединить: «Merge профилей».
- **«Админ лиги не видит чужую лигу»** — так задумано (скоуп); расширить
  или сменить лигу может супер-админ в «Пользователях» → «Лига».
