# ⚙️ SCORESBOX · Справочник настроек: что и где менять

> Если меняете репозиторий, сервер, домен или порт — откройте этот файл.
> Порядок: найдите «что меняете» в таблице → сделайте правки по колонке «Где».

---

## 0. Карта: где что «прописано»

| Параметр | Где живёт | Кто его читает |
|---|---|---|
| **GitHub-репозиторий** | код нигде не хранит имя репо — подставляется сам | Actions, GHCR |
| **Имя Docker-образа** | `cd.yml` → `${{ github.repository }}` (авто) | деплой |
| **Сервер (IP, юзер, ключ)** | GitHub Secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY` | деплой по SSH |
| **Путь на сервере** | `cd.yml` (два места: `cd /opt/scoresbox`) + сами скрипты | деплой |
| **Домен** | DNS A-запись + `SITE_URL` в `.env` на сервере + Secret `DEPLOY_PUBLIC_URL` + `setup-nginx.sh <домен>` | сайт, SSL, health-check |
| **Пароли** | `.env` на сервере (`POSTGRES_PASSWORD`, `ADMIN_PASSWORD`…) + Secrets | БД, админка |

**Важно:** секреты привязаны к конкретному репозиторию. Новый репо = секреты
нужно завести заново (GitHub → Settings → Secrets and variables → Actions).

## 1. Вы сменили репозиторий (например, на `solid-sniffle`)

**Что подхватится само** — ничего менять в коде не надо:
- имя образа на GHCR станет `ghcr.io/artyom-front/solid-sniffle` (из `github.repository`);
- CI/CD запустятся сами (файлы `.github/` уже в репо).

**Что сделать руками (один раз):**

| Шаг | Где | Что |
|---|---|---|
| 1 | GitHub → Settings → Secrets | завести все секреты заново (см. DEPLOY.md §Б8): `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_PUBLIC_URL`, `ADMIN_PASSWORD`… |
| 2 | локальный клон | `git remote set-url origin https://github.com/artyom-front/solid-sniffle.git` |
| 3 | `scripts/deploy.sh`, `rollback.sh`, `docker-compose.prod.yml` | уже сделано в свежем бандле: запасной образ по умолчанию `ghcr.io/artyom-front/solid-sniffle` (CI всё равно подставляет свой) |
| 4 | `DEPLOY.md` и другие гайды | уже сделано в свежем бандле: все команды и ссылки ведут на `solid-sniffle` |

## 2. Вы сменили домен (например, footballday.ru → scoresbox.ru)

| Шаг | Где | Что |
|---|---|---|
| 1 | панель регистратора домена | A-запись: `@` → IP сервера; `www` → тот же IP |
| 2 | сервер, `/opt/scoresbox/.env` | `SITE_URL=https://<новый-домен>` |
| 3 | GitHub Secrets | `DEPLOY_PUBLIC_URL=https://<новый-домен>` |
| 4 | сервер | `sudo ./scripts/setup-nginx.sh <новый-домен>` — nginx + SSL-сертификат Let's Encrypt |
| 5 | дождаться | DNS обновляется до 24 ч (обычно 1–3 ч) |

## 3. Вы сменили сервер (переезд на другой VPS)

| Шаг | Где | Что |
|---|---|---|
| 1 | новый сервер | прогнать шаги Б1–Б4 из DEPLOY.md (софт, Docker, firewall) |
| 2 | новый сервер | забрать код: Б5 (clone репозитория) + `.env` по §Б6 |
| 3 | старый сервер | `bash scripts/backup-db.sh` → забрать файл из `backups/` |
| 4 | новый сервер | восстановить данные по DEPLOY.md §«Восстановление из бэкапа» |
| 5 | GitHub Secrets | `DEPLOY_HOST` = новый IP (+ при смене юзера/ключа — `DEPLOY_USER`, `DEPLOY_SSH_KEY`) |
| 6 | домен | A-запись → новый IP (см. §2 выше) |
| 7 | новый сервер | `sudo ./scripts/setup-nginx.sh <домен>` (SSL выпустится под новый IP) |

## 4. Вы сменили путь на сервере (вместо `/opt/scoresbox`)

| Где | Что |
|---|---|
| `.github/workflows/cd.yml` | 2 места: `cd /opt/scoresbox` в job `deploy` и в job `rollback` |
| сервер | папку создать/перенести, `.env` переложить, шаги А1–А3 по DEPLOY.md |

## 5. Вы сменили порт сайта (не рекомендуется)

По умолчанию всё внутри: контейнер приложения :3000, nginx наружу :80/:443.
Менять нужно только в `deploy/docker-compose.prod.yml` и `scripts/setup-nginx.sh`
— но обычно необходимости нет: наружу смотрит только nginx.

## 6. Что произойдёт, когда всё удачно (happy path)

Цепочка при деплое — по шагам, что вы увидите:

1. **Вы:** `git tag v1.0.8 && git push origin v1.0.8` (деплой запускает ТОЛЬКО тег).
2. **GitHub → Actions, workflow CD** (~5–10 мин): собирается Docker-образ,
   публикуется на `ghcr.io/artyom-front/solid-sniffle:v1.0.8`.
3. **Тот же workflow деплоится на сервер по SSH** (~2–3 мин): бэкап базы →
   миграции → скачивание образа → перезапуск контейнеров.
4. **Health-check:** Actions стучится на `https://<домен>/` — ждёт HTTP 200.
   - 200 → ✅ деплой завершён, джоба зелёная.
   - не 200 → автоматический откат на прошлую версию (джоба Rollback).
5. **Вы открываете `https://<домен>`** — живой сайт: матчи, таблицы, игроки.
   `/admin` — панель управления: первый вход по `ADMIN_PASSWORD`, затем
   включить 2FA (по требованию панели).

**Что нужно ДО первого такого деплоя (один раз):**
сервер подготовлен по DEPLOY.md §Б1–Б8 (софт, код, `.env`, nginx, секреты)
и домен направлен A-записью на IP сервера. Без этого тег запустит CD,
но деплей упадёт на шаге SSH/health-check — и сам откатится, ничего не сломав.
